## Lab Activity 6: Discussion

- **Firestore User Structure:** When initiating a chat, the application retrieves users from the "Users" collection in Cloud Firestore. Each document represents a user, requiring a `uid` field (linked to Firebase Auth) to successfully establish a unique communication channel. Messages are stored within a "chat_rooms" collection. The specific chat room document ID is generated by combining the two interacting users' sorted UIDs, ensuring that both users are writing to and reading from the exact same subcollection of "messages."
- **Chatting Yourself:** Because the chat room ID relies on sorting the two participant UIDs, initiating a chat with yourself would result in the two identical UIDs being joined together. The application architecture technically permits it—you would send a message to a document path where your UID is both the sender and receiver. However, to prevent UI redundancy, this implementation proactively excludes the currently authenticated user's email from populating in the `ChatScreen` list view, rendering it inaccessible by default.
